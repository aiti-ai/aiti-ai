## 三、惯犯坑（下次合并前必读）

1. **TS 6 `transpileModule` 会加 `"use strict";` 前缀**（TS 5 不加）：上游 AST 抽取型测试
   （`fork-draft` / `clone-command` / `startup-notices` 的 `new Function("scope", "with(scope){ return <fn>; }")`
   模式）会变成返回字符串 → `run is not a function`。**修法：transpile 的 compilerOptions 加
   `alwaysStrict: false`**。上游每新增此类测试都要补（本次修了 3 个文件）。
2. **上游 jiti 链测试撞 fork 的 useI18n**：上游 useAgentSession 不依赖 useI18n，fork 依赖
   （`useI18n.tsx` 含 JSX）→ 上游新 hook 测试的 `createJiti` 需补
   `jsx:{runtime:"automatic"}` + `"react/jsx-runtime"` shim + `"@/hooks/useI18n"` stub +
   `"@": process.cwd()`；**不能带 `tsconfigPaths: true`**（paths 插件会抢在 alias 前把
   `@/hooks/useI18n` 解析到真文件）。样板 = `agent-phase.test.mjs` / `send-recovery.test.mjs`。
3. **draft-keeper 间接层**：fork 的 `restoreSubmission` 走 `applyDraftIntent`（未注册 keeper 时
   直接 return），上游测试直接读 draft-store → 需 `registerDraftApi` 迷你 keeper 桩
   （`send-recovery.test.mjs` 样板，合并语义与生产一致）。
4. **fork running 闸回潮**：上游持续给 clone/fork/fork_branch/navigate_tree 加
   `isSessionRunningForReplacement()` / `shellRunning` 闸；fork 策略 = 运行中可用。合并时遇到
   即删（`lib/rpc-manager.test.mjs` "concurrent replacements…" 钉测试会拦），删后确认
   `isSessionRunningForReplacement` 仍有其他调用点（lease/shutdown 路径在用）。
5. **basePath 红线**：上游新代码裸 `fetch("/api/...")` → 包 `apiUrl()`（本次 `readIdleMessages`
   一处）；`lib/base-path-sweep.test.mjs` 会拦。
6. **源码钉测试冲突区**（改产品代码后同步改 pin，写法见各测试内 2026-11-12 注释）：
   `onFork` 融合形态（`handleFork`→`forkFromMessage`，三处钉）、`loadSession` 的
   `{ force: true }` 计数（现 **2** 处合法：mount + run 末 idle 强制读）、clone 的
   `leafId: appended?.base === activeLeafId` 精化、`handleAbort` 的 bash 分支条件前缀。
7. **loadSession flight 无条件注册**：上游 idle-read 靠 `pendingReads` 等待 `force:` flight，
   fork 旧的 `if (!bypass)` 跳注册会让等待失明 → 注册必须无条件（fork 的 bypass 只影响
   join，不影响注册）。
