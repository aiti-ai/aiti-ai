## 一、上游带入的功能（aiti fork 已消化并适配）

### 1. Side chats（`/side`）— 本波最大特性（#1469 系）

- 会话可分叉出**侧聊**：不影响主会话运行，独立上下文提问（`POST /api/sessions/[id]/fork`，side 分派）。
- 侧聊元数据落盘（`pi-web:side` custom entry），与主会话构成 family 关系；折叠进主行显示。
- Agents 切换器（右侧面板）统一承载子代理与侧聊（`SessionChatPanel` 替代原 SubagentViewer/SideChatPanel 双组件）。
- 侧聊**静默完成**：完成不通知、不记未读（`isHiddenRelation` 泛化门控）。
- 侧聊标签随主会话恢复（跨刷新、跨项目切换记忆）。
- 侧聊不可 fork/clone（守卫 `refuseForkOfSideChat`），不可归档。
- 删除侧聊单独删；删主会话连带全家。

### 2. 归档视图折叠组（#1351 系）

- 归档视图按项目分组，组头可**折叠/展开**（Alt+点击全部跟随），状态存浏览器 localStorage。
- 组头 ⋯ 菜单：全部恢复 / 全部删除（带确认）。
- 空项目组出现 "Pin to keep"（#1476：无会话项目仅靠 pin 保留在列表）。

### 3. 模型选择器增强

- **provider 显示名**（#1514）：分组头显示 "DeepSeek" 而非 `deepseek`；`providerName` 全链路
  （models API → 缓存 → hook → 选择器）。fork 的模型可用性标注（429/错误/未探测徽标）保留并叠加。
- **model scope 切换**（#1503/#1486）：`enabledModels` 收窄时出现 "scoped | all" 切换行，
  切到 all 才加载全量列表（`GET /api/models?scope=all`）；Tab 键快捷切换。
- 默认星标只在 scope 内可保存（`PUT /api/models/default` 拒绝范围外模型）。

### 4. 标签页拖拽重排（#1511）

- 右侧面板标签可拖拽排序（插入位置指示线 + Alt+方向键），顺序持久化（`lib/panel-tab-order.ts`）。
- 关闭的标签自动移出保存的顺序；重开按新标签追加。

### 5. 沙箱 HTML 预览存储修复（#1494）

- 大 HTML（≤10MB）预览不再拼半截文档：超块读时整文件经下载通道取回
  （fork 通道：票据 POST，路径不入 URL），注入沙箱 polyfill 后进 `iframe srcDoc`。

### 6. 移动端设置重构（一级一屏）

- 手机上 Settings 变为**逐级导航**（列表 → 分区 → 行详情），带滑动动画与系统返回键支持；
- 桌面保持原双栏。fork 的桌面分区标签页（settings-section-tabs）保留。
- Agents 按钮在窄屏手机上移出 ⋯ 菜单、独立放在工具条上（badge 常显）。

### 7. 通知去重（#1515/#1518）

- 页面自己提示过的完成通知，推送在 10 秒内**静默替换**（不二次响铃）；
  更早的任务通知照常提醒（#701 语义保留）。
- fork 的「会话完成通知上限 3 条、自动关最旧」逻辑保留，两层去重融合。

### 8. 其他

## 二、fork 决策台账（冲突以谁为准、为什么）

### 保我方（fork 语义为准，上游等价实现未采纳）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **运行中可 fork/clone**：不采纳上游 `isBashRunning` / `isSessionRunningForReplacement` 守卫 | fork 的设计基线（用户明确拍板过）：fork 只复制文件、不关源会话；跨实例孤儿运行已处理。采纳了上游新增的 `refuseForkOfSideChat`（侧聊拒绝复制——fork 原语的超集守卫） |
| 2 | **modelSwitchPending 徽标语义**：运行中切模型 = 下轮生效 + 角标提示 + 切回即取消 | 上游 #1527 是 live-state 立即生效 + 同步刷新。fork 的延迟生效是刻意 UX（角标让用户知道"下轮才换"）；上游的 midRun 清 override 分支不采 |
| 3 | **流式渲染架构**：保留 fork 的 200ms 节流 + MemoizedMarkdown + streamState/tps 徽标 | 上游 #1520 引入 streamingStore/messageKeys + 逐块 memo 的 StreamingReply。fork 方案已解决同问题（O(n²)→节流）且有 fork 测试钉住；未采纳架构但采纳其稳定化语义目标 |
| 4 | **MessageView 紧凑 meta 行**：model+用量+估算 token+tps 徽标+复制+时间 单行 | 上游拆成 AssistantMessageHeader + stats 双行。fork 行是降高度设计（含上游新增的 est/tps 信息） |
| 5 | **MarkdownBody 渲染管线**：200ms 节流 + 段落点击扩展点 + 数学懒加载 + user 消息 HTML 转义 | 上游的块拆分 memo（splitMarkdownBlocks）与 fork 节流同目标不同手段；采纳上游新插件档位（keepTextLayout / documentRehype）接入 fork 管线 |
| 6 | **SessionTree 行结构**：`<button class="session-tree-main">`（处理器导航） | 上游改为 `<a href="?session=…">` 锚点。fork 行需要携带队列/草稿/分支等复杂交互，锚点化是侵入式改造；isHiddenRelation 泛化采纳 |

| 8 | **quote 弹层双流程**：fork 的 "Ask in new chat"（fork_branch 到引用条目）与上游的 "Ask in side chat" 并存 | 两个语义不同（独立会话 vs 侧聊），由 quoteFlow 状态分派；有 entry 追踪（fork）与 bash 运行守卫 |
| 9 | **模型切换 pending 角标、顶栏自定义排布、会话队列/恢复全家族**、PATCH（patch-package）、测试 ForceExit | fork 基线特性，上游无可比替代 |

## 五、部署注意事项：版本号三层链（历次合并惯犯坑）

UI 显示的版本号（点击标题 scramble 显示 `X.Y.Zp<pi版本>`）是一条三层链，**任何一层没走完就显示旧值**：

1. **`package.json` 的 `version`** — 上游 Release commit 会改它，fork 侧若也改过则必冲突；
   conflict resolution 选错边就悄悄留旧值（v0.13 波踩过：留了 0.12.2，`adf8597b` 专门修复）。
   **合并收尾核对：package.json version == 上游最新 release tag**。
2. **构建内联** — `NEXT_PUBLIC_APP_VERSION` 在 build / dev 启动时由 next.config.ts 读 package.json
   注入（编译期内联进 chunk）。改了 package.json 不重新 build / 不重启 dev = 产物里还是旧值。
3. **运行实例** — dev/prod 进程不重启，页面（含编译缓存）永远是旧版本的渲染结果。

本次实际发生：合并本身正确带入 0.15.0，但 dev/prod 实例未立即重启 → UI 仍显示 0.13（用户报告）；
重启两者并刷新依赖后，浏览器实测标题定版 `0.15.0p1.5.0` ✓。下次合并 SOP 第 11 步已固化此核对
（见 aiti-ai `docs/pi-web-merge-notes.md` §7.3 / §3 第 11 步）。
