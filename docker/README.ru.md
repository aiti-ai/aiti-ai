# AITI Web — официальные Docker-образы (core / full)

[English](https://github.com/aiti-ai/aiti-ai/blob/main/docker/README.md) | [中文](https://github.com/aiti-ai/aiti-ai/blob/main/docker/README.zh-CN.md) | [日本語](https://github.com/aiti-ai/aiti-ai/blob/main/docker/README.ja.md) | Русский

**AITI Web** (`@aiti-ai/pi-web`) — браузерный рабочий стол для агента [pi coding agent](https://github.com/earendil-works/pi). Это форк апстримного [pi-web](https://github.com/agegr/pi-web), выросший в самостоятельный дистрибутив **aiti**, созданный для реального ежедневного использования: 63+ встроенных расширений (сессии и очереди, git-инструментарий, отладка через внедрение в страницы, мультиагентные бэкенды, туннели, голос) без установки по одному; движок остаётся pi (общие JSONL-сессии, та же локальная конфигурация).

Этот образ — самый быстрый способ запустить всё сразу: pi-web + все встроенные расширения + движок pi + Node/git + aiti-bridge в одном контейнере; `full` добавляет веб-рабочий стол (noVNC, Chrome/CDP), голос и туннели. История форка: [aiti.pw/guide/origin.html](https://aiti.pw/guide/origin.html).

Документация: [aiti.pw](https://aiti.pw/) (EN / 中文) · Исходный код: [aiti-ai/aiti-ai](https://github.com/aiti-ai/aiti-ai) · Предпочитаете npm? `npm i -g @aiti-ai/pi-web` · Лицензия: [MIT](https://github.com/aiti-ai/aiti-ai/blob/main/LICENSE)

# Руководство по использованию

> Образы: `aitiai/pi-web:core` (базовый, 2.13GB) / `aitiai/pi-web:full` (всё в одном, 7.76GB).

## 1. Быстрый старт

```bash
# Базовый образ: откройте http://localhost:30144 — полный рабочий стол
docker run -d --name aiti --init \
  -p 30144:30142 \
  -v aiti_data:/opt/aiti/data \
  -v aiti_agent:/opt/aiti/agent \
  -v ~/my-project:/workspace \
  aitiai/pi-web:core
```

- Первый запуск: в боковой панели «Выбрать проект → Использовать каталог по умолчанию» (= /workspace) → «Новая сессия» → «Настройки» внизу, чтобы указать ключ модели → чат.
- Данные хранятся в двух томах: `aiti_data` (данные расширений во время выполнения) и `aiti_agent` (сессии pi / конфигурация моделей) — **при обновлении образа данные сохраняются**.
- ⚠ Монтируйте только под пути `/opt/aiti`, **никогда не монтируйте весь `/opt/aiti`**: именованный том наполняется лишь однажды, поэтому монтирование корня навсегда сделает обновления образа недействительными (см. тест-отчёт O22).

## 2. Выбор образа

| | core | full |
|---|---|---|
| Размер | 2.13GB | 7.76GB |
| pi-web + встроенные расширения + движок pi + justget + bridge | ✅ | ✅ |
| GUI (Xvfb/VNC/noVNC/Chrome+CDP) | — | ✅ |
| Распознавание речи ASR (funasr, четыре модели, :8767) | — | ✅ |
| TTS edge-tts / веб-терминал ttyd (:7681) | — | ✅ |
| Туннели cloudflared/ngrok/frpc | — | ✅ |
| Минимум памяти | 1GB | **8GB** (full + голос; при 2–6GB — OOM) |

Дополнительные фазы full управляются через `AITI_PHASES` (см. §4).

## 3. Порты

| Порт | Сервис | По умолчанию |
|---|---|---|
| 30142 | Главный интерфейс pi-web | пробросить обязательно |
| 8777 | aiti-bridge (внедрение в страницы / MCP / REST для агентов) | проброс при использовании внешних агентов / внедрения |
| 8767 | ASR WS/HTTP (full) | включён в full по умолчанию; проброс по необходимости |
| 6080 | Веб-рабочий стол noVNC (full) | только loopback, проброс по необходимости |
| 5900 | VNC (full) | только loopback |
| 9222 | Chrome CDP (full) | только loopback |
| 7681 | Веб-терминал ttyd (full) | только loopback |

`AITI_PIWEB_PORT` / `AITI_BRIDGE_PORT` меняют порты на стороне контейнера (редко нужно).

## 4. Переменные окружения

| Переменная | По умолчанию | Значение |
|---|---|---|
| `AITI_PHASES` | `piweb,bridge` | Через запятую: `piweb,bridge,gui,asr,term`. gui/asr/term реализованы только в full (core пишет в лог и пропускает) |
| `PUID`/`PGID` | 1000 | uid/gid выполнения (согласуйте с пользователем хоста, чтобы примонтированные каталоги работали сразу). ⚠ Не используйте `UID` (read-only встроенная переменная bash) |
| `TZ` | UTC | например `Asia/Shanghai` |
| `AITI_PIWEB_PORT` / `AITI_BRIDGE_PORT` | 30142 / 8777 | Порты на стороне контейнера; HEALTHCHECK следует за ними автоматически |
| `AITI_MODE` | auto | `core`/`full`/`auto` (по маркеру слоя образа); установка core на образе full понижает до базовых фаз |
| `AITI_DEV` | 0 | `1` = монтировать исходники и запускать `next dev` с горячей перезагрузкой (режим разработки) |
| `AITI_SKIP_CHOWN` | 0 | `1` = пропустить инициализацию под root при прямом запуске с `--user` |
| `AITI_GUI_NOFILE` | 65536 | Лимит fd для GUI-сессии (не увеличивать — большой NOFILE вешает x11vnc, тест-отчёт O20) |
| `AITI_GUI_SIZE` | 1920x1080x24 | Разрешение виртуального дисплея |

### Домен / обратный прокси (та же семантика, что у pi-web)

| Переменная | Значение |
|---|---|
| `PI_WEB_ALLOWED_HOSTS` | Доверенные имена хостов (через запятую) — домены обратного прокси **обязательно** указывать, иначе запросы получают 403. Неперечисленные хосты по-прежнему отклоняются (гейт Host сохраняется) |
| `PI_WEB_BASE_DOMAIN` | Домен для формирования URL проброса service-tunnels (`host:port`) |
| `AITI_BASE_URL` | Публичный базовый URL для страниц внедрения aiti-devtools / MCP (укажите URL вашего прокси) |
| `API_ALLOW_ORIGINS` | CORS моста (`*` или явные origin; нужен, когда домен прокси отличается от origin раздачи) |
| `PI_WEB_EXTRA_EXTENSIONS_DIRS` | Дополнительные каталоги расширений (пути внутри контейнера, через запятую; в паре с монтированием `-v` для пользовательских расширений) |

Пример обратного прокси (домен → `127.0.0.1:30144`, мост → `18777`):

```bash
docker run -d --name aiti --init \
  -p 127.0.0.1:30144:30142 -p 127.0.0.1:18777:8777 \
  -e PI_WEB_ALLOWED_HOSTS="pi.example.com,aiti.pi.example.com" \
  -e PI_WEB_BASE_DOMAIN="pi.example.com:8443" \
  -e AITI_BASE_URL="https://aiti.pi.example.com:8443" \
  -e API_ALLOW_ORIGINS="*" \
  -v aiti_data:/opt/aiti/data -v aiti_agent:/opt/aiti/agent \
  aitiai/pi-web:core
```

Измеренное поведение (тест-отчёты T-E/T-H): перечисленные Host отвечают 200, неперечисленные — 403; добавление поддоменов под wildcard `*.pi.example.com` + wildcard-сертификат не требует дополнительных действий.

## 5. Тома и персистентность

| Монтирование | Содержимое | Рекомендация |
|---|---|---|
| `/opt/aiti/data` | Данные расширений (конфиг-хранилище / индексы / кэши) | Именованный том |
| `/opt/aiti/agent` | JSONL сессий pi / models.json / mcp-cache | Именованный том (**жизненно важно — всегда сохраняйте**) |
| `/workspace` | Рабочая область (cwd по умолчанию при запуске; сессии pi группируются по проектам) | Bind-mount каталога проекта хоста |
| `/home/aiti/.pi` | **Опционально**: наследовать конфигурацию pi хоста | При первом запуске принимает auth.json/models.json; settings.json объединяется через jq со встроенными значениями по умолчанию (ключи пользователя выигрывают, packages — объединение) |
| `/opt/aiti/extensions` | Код расширений | **Не монтировать** — принадлежит слою образа; обновляется вместе с образом |

## 6. Возможности full-образа вкратце

| Функция | Точка входа |
|---|---|
| Веб-рабочий стол | noVNC `:6080/vnc.html` (RFB через websockify→x11vnc→Xvfb :99) |
| CDP-отладка | Chrome `:9222` (headful, `--user-data-dir=/opt/aiti/data/chrome-profile`) |
| Голосовой ввод | ASR `ws://<host>:8767/ws/stream` (реальное время) / `/voice/quick` (быстрый) / `/voice/transcribe` (точный) / `/ws/vad` (сегментация) — расширение aiti-ai-input подключается автоматически через `AITI_ASR_STREAM_BASE` |
| Озвучивание | edge-tts установлен; включите feature `tts.edge` в расширении aiti-ai-speak |
| Веб-терминал | ttyd `:7681` |
| Туннели | `cloudflared` / `ngrok` / `frpc` доступны внутри контейнера (ngrok требует ваш authtoken) |
| Инструмент загрузки | `justget <url> -o <file> -m <mirror-url>` многопоточное соперничество источников |

## 7. Эксплуатация

```bash
docker logs -f aiti                 # логи (готовность расширений / мост / баннер — всё здесь)
docker exec -it aiti bash           # внутрь контейнера (пользователь aiti, sudo без пароля)
docker stats aiti                   # ресурсы
docker inspect aiti --format '{{.State.Health.Status}}'   # healthy = всё в порядке
docker stop aiti && docker rm aiti  # остановить и удалить (тома сохраняются)
docker volume rm aiti_data aiti_agent   # удалить и данные (осторожно)
```

- **Плавная остановка**: `docker stop` завершается примерно за 1 с (entrypoint пересылает сигналы каждому сервису).
- **Обновление**: `docker pull` нового образа, затем удалите и пересоздайте контейнер (одноимённые тома переносят данные); расширения обновляются вместе с образом.
- **Пересборка + смоук**: `./docker/scripts/rebuild-and-smoke.sh core full` (готово для CI; код выхода = число провалов).

## 8. Сборка и публикация (для мейнтейнеров)

```bash
# Не-CN сеть / GitHub CI: официальные зеркала напрямую
./docker/build.sh --target core --tag aitiai/pi-web:core
./docker/build.sh --target full --tag aitiai/pi-web:full     # сначала нужен core

# Локальная сборка в CN: --cn подставляет зеркала (apt=tuna / npm=npmmirror / hf=hf-mirror / pypi=tuna)
./docker/build.sh --target core --tag aitiai/pi-web:core --cn
# Эквивалент через env: AITI_CN=1 (предустановлено в шаблоне systemd-юнита)

./docker/scripts/smoke.sh full [--keep]                  # смоук-набор из 22 проверок (код выхода = число провалов)
node docker/scripts/e2e-ui.mjs                           # E2E пользовательского сценария (нужны playwright-core + chromium)
node docker/scripts/gen-deps.mjs                         # матрица зависимостей S3 (читает блоки метаданных `aiti` расширений)
```

> `--cn` влияет только на зеркала публичных источников; **приватный реестр `@aiti-ai/*` — отдельный временный канал**: `--private-registry <url приватного реестра>` (или env `AITI_PRIVATE_REGISTRY`) — только для локального тестирования. Когда `@aiti-ai/*` появится на публичном npm, опустите его — будет использоваться официальный реестр.
> То же в рантайме: `docker run -e AITI_NPM_REGISTRY=<url приватного реестра>` позволяет pi скачивать приватные пакеты при первом запуске (прописывается в `~/.npmrc` внутри контейнера).
> Известные ограничения (см. раздел оставшихся проблем тест-отчёта): для arm64 нет официального Chrome (нет CDP; остальные слои загрузки готовы); загрузки ngrok/frpc иногда требуют повторов (в сборке есть гоночный фолбэк через gh-mirror); UI E2E зависит от chromium на хосте.

## 9. Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| Контейнер циклически перезапускается | Смотрите первую ошибку в `docker logs`; обычно конфликт портов / права на тома (согласуйте PUID) |
| Обратный прокси 403 | Домен не указан в `PI_WEB_ALLOWED_HOSTS` |
| `/api/models` 403 | Нормально — разрешены только cwd существующих сессий; health-чек использует `/api/home` |
| x11vnc подключается, но картинки нет / очень медленно | Дедлок NOFILE (O20) — убедитесь, что `AITI_GUI_NOFILE` не увеличивали, и используйте собственный 50-gui-start образа |
| CDP 9222 недоступен | Убедитесь, что среди флагов есть `--user-data-dir` (Chrome 136+ игнорирует CDP на профиле по умолчанию) + EULA первого запуска пропущена |
| Первый отклик ASR медленный | Модели загружаются лениво (full предзагружает 2.7GB, повторная загрузка не нужна; смена модели докачивает инкрементально) |
| OOM | full + голос требует ≥8GB памяти (на практике 2–6GB — OOM, тест-отчёт T-H5) |
